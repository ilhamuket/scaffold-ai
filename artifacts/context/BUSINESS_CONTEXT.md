# BUSINESS_CONTEXT

## Founder Intent
Use this scaffold as a controlled AI operating system for projects that already exist or will be contributed later. The founder remains the final decision maker for product direction, architecture tradeoffs, release approval, security exceptions, and infrastructure spend.

## Business Model
Not selected yet. The business model belongs to the future target project and must be confirmed during intake.

## Revenue Logic
Not selected yet. Revenue assumptions must not be invented before the target project context is available.

## Constraints
- budget: not_selected_until_target_project_available
- timeline: not_selected_until_target_project_available
- team: founder-led, AI-assisted, future contributor project pending
- legal/compliance: unknown until target project is attached
- infrastructure: unknown until target project is attached

## Competitive Angle
The scaffold's advantage is operating discipline: intake first, impact scan second, and scoped implementation only after the existing project shape is understood.

## Risks
- Treating the scaffold as a greenfield product starter before the target project exists.
- Selecting frameworks, database, or architecture without evidence from the future contributor repository.
- Running build or QA steps before a real project route and first change scope are defined.
