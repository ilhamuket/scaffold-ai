# PRODUCT_SCOPE

## In Scope
- Prepare the scaffold for future existing-project onboarding.
- Keep source-of-truth docs aligned around the current status: target project not attached yet.
- Maintain intake and impact-scan placeholders for the future contributor repository.
- Preserve manual gate control before official workflow steps.

## Out of Scope
- Building a product application inside this scaffold before a target project exists.
- Selecting frontend framework, backend framework, database, testing stack, or deployment route.
- Filling `development/` with a fake app structure.
- Marking intake, impact scan, build readiness, QA readiness, or release readiness as complete.

## MVP Features
- Clear pre-onboarding project context.
- One active task for scaffold preparation.
- Explicit workflow blocker: target repository not attached.
- Pending intake and impact-scan artifacts ready for future use.

## Phase 2 Features
- Run existing-project intake after the contributor repository path or URL is available.
- Run impact scan for one scoped feature, fix, redesign, migration, refactor, or cleanup slice.
- Continue into requirements, flows, design, architecture, sprint planning, build, QA, and release only after gates are satisfied.

## Actors
- founder/admin
- future contributor/maintainer
- Codex runtime
- Claude runtime
- specialized workflow agents
- target project users, devices, services, and operators to be confirmed during intake
