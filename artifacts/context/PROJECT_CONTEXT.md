# PROJECT_CONTEXT

## Project Name
Project Scaffold For Future Existing-Project Onboarding

## One-Sentence Summary
This scaffold is an AI operating system for onboarding and safely evolving a contributor-provided project that already exists.

## Product Type
- not_selected_until_target_project_available
- Candidate modes remain: software_saas / software_iot_sync / internal_ops_system / ai_marketing_engine

## Primary Goal
Prepare documentation, workflow state, and intake checklists so a future contributor repository can be audited before any implementation work begins.

## Current Stage
- pre_onboarding
- target_project_not_attached

## Platforms
- not_selected_until_target_project_available
- Possible platforms will be confirmed from the target repository during existing-project intake.

## Problem Being Solved
The founder needs a repeatable way for Codex and Claude to inspect an existing or inherited project, preserve its working conventions, and scope changes before coding.

## Core Users
- Founder as the only human decision maker.
- AI runtimes and agents using this scaffold for structured intake, planning, build, QA, and release support.
- Future contributors or maintainers whose project will be onboarded into this scaffold.

## Success Definition
Before the target repository is available, success means the scaffold clearly states that no product stack has been audited yet and is ready for future intake. After the target repository is attached, success means the current stack, active routes, modules, constraints, and first change scope are documented before implementation.
